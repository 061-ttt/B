# 水産マップ

小学5年 社会科「水産業のさかんな地域」第1時のためのWebアプリ。家から持ってきた魚の値札の「産地」をクラス全員で入力すると、端のない3Dの地球儀にピンが集まり、件数が増えるほどピンが大きくなる。寒流・暖流・潮目・海の深さを重ねて、「なぜその地域に水産業がさかんなのか」という単元を貫く問いを立てる。

設計に使ったプロンプトは [docs/PROMPT.md](docs/PROMPT.md)。

## 授業での使い方

**先生**

1. 電子黒板やタブレットで開き、右上の 👥 →「先生：クラスをつくる」
2. 大きなQRコードが画面いっぱいに出るので、そのまま電子黒板に映す（6文字のコードも出る）
3. 子どもの入力がリアルタイムに集まる。「すべて」「暖流の魚」「寒流の魚」で絞り込んで分布を比べる
4. 「日本」「世界」で地球儀を寄せたり引いたりし、右上のレイヤーボタンで海流・深さ・名前の表示を切りかえて根拠を探す

**子ども**

1. タブレットのカメラでQRコードを読む。アプリを開いている場合は 👥 →「QRコードを読み取って参加」でも読める。コードを入力してもよい（名前は入れない。班だけ）
2. ＋ボタン → 値札の文字をそのまま入れて「読み取る」（声でも入力できる）、または魚と産地を選ぶ →「地図にのせる」
3. 図鑑で魚をタップすると、産地・寒流/暖流・とり方・旬・「なぜ？」が開く。「地球儀で産地を見る」で主な産地に輪が出る
4. シート画面で「事実／理由の予想／次に調べたいこと」を書き、ふり返りにチェックする。「地球儀から読み取る」で数えた事実が入り、「問いのたね」で次の問いの候補が出る。シートに書いたことはそのタブレットだけに保存され、ほかの人には見えない（共有されるのは地球儀に入力した魚と産地だけ）

ネットワークが切れても、その端末に保存して授業を続けられる。つながると自動で送り直す。

## 機能と依頼内容の対応

| 依頼 | 実装 |
|---|---|
| 立体的な地図（Google Earth のような球体、端がない） | Three.js の地球儀。陸地を球面に沿って押し出し、大気の光と星空をつけた。ドラッグで回し、ピンチで宇宙から日本の港の近くまで寄れる。近いほどゆっくり回る。開くと宇宙から日本へ寄っていく。日付変更線や世界地図の切れ目はない |
| 魚のデザインと名前のピンが浮き上がる | 魚（3種）・えび・いか・たこ・貝・かに・海藻・卵・うなぎの11種類のシルエット。ピンは茎が伸びてバネのように浮き上がる |
| データが1つのアプリに集約、件数でピンが大きくなる | Durable Object（クラスごと）＋WebSocketでリアルタイム集約。同じ産地でも魚の種類ごとに別のピンにし、同じ産地のピンは重ならないよう縦に積む。ピンの大きさはその魚の件数の平方根に比例（面積が件数に比例）。地球儀を引くと国内の産地は「日本」にまとまり（魚の種類ごとには分けたまま）、寄ると産地ごとに分かれる |
| 寒流（青）・暖流（赤）が動きながら流れる | 細かい矢印（InstancedMesh）が球面に沿って流れ、引いて見るときは矢印が大きくなる。日本は黒潮・対馬海流・親潮・リマン海流、世界は主要な20以上の海流 |
| 寒流と暖流がぶつかる所は赤と青の両方 | 潮目は赤と青の矢印を交互に流し、赤と青の帯を並べて表示（日本の三陸沖、北大西洋、南大西洋） |
| 海洋の深さごとのグラデーション（大陸棚など） | 全球の深さ図（2048×1024）に、日本付近だけ約7倍細かい深さ図を重ねる。大陸棚（〜200m）・大陸斜面・深海・海溝を色分け。東シナ海・オホーツク海北部・ベーリング海などの広い大陸棚、日本海溝・千島海溝・伊豆小笠原海溝・マリアナ海溝などを反映。大陸棚の縁（200m）を細く強調 |
| メモ・タスク・印刷 | ご要望によりメモ欄・タスク・印刷ボタンは削除。以前の版で作られたメモやタスクのデータも、開いたときに自動で消す |
| 絞り込み | 「すべて」「暖流の魚」「寒流の魚」の3つ |
| シートは自分のタブレットだけ | 事実・理由の予想・次に調べたいこと・ふり返りは、そのタブレットの中（localStorage）だけに保存し、サーバーには送らない。地球儀に入力した魚と産地だけがクラスで共有される |
| 高レベルのビジュアル（黒ベース） | 宇宙の黒に、光る枠（暖流＝赤、寒流＝青、両方＝紫）、色ちがいの番号バッジ（01〜05）、丸ゴシックの太字、光が当たったような立体感のある魚のアイコン、光るレンズが動くタブバー |
| アニメーションを多用 | ピンの上昇・件数増加のはずみ、地図切りかえ時のカメラ移動、シートのバネ、アコーディオン、カードの出入り、トースト。端末の「視差効果を減らす」設定では止める |
| 全画面スケルトンローディング | 最初の描画からHTMLで全画面の骨組み（地球儀の丸を含む）を表示し、地球儀の準備ができたらフェードアウト |
| 余計なキャッチコピーなし | ラベルは機能を示す語だけ |
| 60人が同時に入力しても即時反映 | 入力はWebSocketで送り、Durable Object が15ミリ秒ごとにまとめて全員へ配る。受け取る側も30ミリ秒ごとにまとめて描く。同じ入力が2回届いても1件だけ保存（送り直しに強い）。人数の知らせもまとめて送る。1クラス150台・3000件まで |
| QRコードで参加 | クラスをつくると大きなQRコードが出る（電子黒板向け）。アプリ内のカメラでも読み取れる（BarcodeDetector、ない端末は jsQR）。アプリ自体を開くQRコードも出せる |
| 魚のデザインに実際の写真 | 図鑑の30種すべてに、Wikimedia Commons の自由に使える写真（パブリックドメイン・CC0・CC BY・CC BY-SA）を使う。図鑑・ピン・入力候補に表示し、図鑑に撮影者とライセンスを表示。写真は WebP に縮小して同梱（合計約0.8MB） |
| 魚の情報をアコーディオンで | 図鑑30種（ひらまさを追加）。タップで開閉し、地図の絞り込みと連動 |
| Workers AI | 値札の文字列から魚・産地・天然/養殖を抽出、集計から「問いのたね」を生成（答えは書かせない）。AIが使えないときは規則ベースに自動で切りかわる |

## 技術選定と理由

| 領域 | 選んだもの | 理由 |
|---|---|---|
| 書体 | **M PLUS Rounded 1c ＋ Outfit**（端末に同梱） | 丸ゴシックは5年生に読みやすく、親しみがある。数字とバッジは幾何学的な Outfit で大きく見せる。日本語は文字の範囲ごとに分割されていて、使う字の分だけ読み込む。外部サービスを使わないので学校のフィルタリングでも表示が崩れない |
| UIの土台 | **Preact + Signals** | React互換の書き方で約4KB。学校の古いタブレットや弱い回線でも最初の表示が速い。Signals は値が変わった部分だけを更新するので、ピンが増え続ける集約画面でも全体を描き直さない |
| ビルド | **Vite** | 開発時の反映が速く、3D地図の部分を別ファイルに分けて後から読み込める（コード分割）。同じ設定で1ファイル版（サーバーなしで動く版）も作れる |
| 言語 | **TypeScript** | 魚・産地・入力データの形を型で固定し、フロントとWorkerで同じ定義・同じ辞書を使い回せる |
| 3D地球儀 | **Three.js**（OrbitControls） | 球体・陸地の押し出し・インスタンス描画（大量の矢印を1回で描く）・カメラ操作がそろっている。Google Earth などの地図タイルの外部サービスに頼らないので、学校のフィルタリングやオフラインでも地球儀が出て、利用規約や費用の心配もない |
| 地図データ | **Natural Earth（world-atlas）＋ d3-geo** | パブリックドメインで教材に使いやすい。ビルド時に経緯度の軽いJSONにする。日本だけ1:1000万の精細なデータに差しかえ、世界は1:5000万 |
| 海の深さ | 端末内で計算する模式図 | 海岸からの距離（距離変換）で細い大陸棚・斜面・深海を作り、広い大陸棚と海溝を重ねて、地球儀にはる画像にする。外部の大きな地形データを読み込まずに、学習に必要な「大陸棚」「海溝」の違いが分かる |
| アニメーション | CSS（バネ曲線）＋ Web Animations API | ライブラリを足さず、GPUで動くtransformとopacityだけを動かす。動きを減らす設定も一括で尊重できる |
| 配信・API | **Cloudflare Workers（静的アセット）＋ Hono** | 画面とAPIを1つのWorkerで配信。世界中の拠点から近い所で応答する。Honoは小さく、Workers向けに作られたルーター |
| クラスのデータ | **Durable Objects（SQLiteストレージ）** | 1クラス＝1インスタンスなので、同時に30台が書いても順番が保証される。WebSocketを持てるのでリアルタイム配信がそのままできる。ハイバネーションで、授業中に誰も操作していない間はほぼ費用がかからない。D1やKVより「クラスという単位」に素直に合う |
| リアルタイム | WebSocket（Hibernation API） | ping は眠ったまま自動応答。切れたら指数バックオフで再接続し、未送信分を送り直す |
| AI | **Workers AI**（Llama 3.1 8B fast：読み取り／Llama 3.3 70B fast：問いのたね） | 同じCloudflare内で動き、外部APIキーが要らない。読み取りは速さ重視の小さいモデルとJSONスキーマ出力、問いづくりは日本語の質重視の大きいモデル。出力は必ず辞書と照合し、問いの形でないものは捨てる。モデルは環境変数で差し替え可能 |
| オフライン | localStorage ＋ 送信待ちキュー | 授業中に回線が落ちても入力が消えない |
| QRコード | qrcode-generator ＋ jsQR | 表示は依存なしで小さく、SVGで鮮明。読み取りは端末の BarcodeDetector を優先し、使えない端末（iPadのSafariなど）では jsQR を必要なときだけ読み込む |
| 魚の写真 | Wikimedia Commons | 教材に使ってよいライセンスの写真が種ごとにそろっている。WebP に縮小してアプリに同梱するので、オフラインでも学校のフィルタリング下でも表示できる |
| テスト | **Vitest**（単体）＋ **Playwright**（実ブラウザE2E） | 解析・集計・球面の座標・入力検査は単体テスト、スケルトン・地球儀・海流・リアルタイム同期・シートが共有されないことは実際のChromeで操作して確認 |
| CI/CD | GitHub Actions ＋ wrangler | pushごとに型・単体・E2Eを実行し、mainはCloudflareへ自動デプロイ |

## 個人情報と安全

- 名前を入力させない（班番号だけ）。端末はランダムなIDで区別する
- クラスのデータは作成から30日で自動削除（Durable Object のアラーム）
- サーバー側で入力を検査（辞書にない産地・魚IDは拒否、文字数制限、HTMLタグ除去、1台1分30件まで、1クラス800件まで）
- 入力を消せるのは入力した端末と、クラスをつくった先生（先生キーはハッシュで保存）
- AIは答えを書かず問いだけを返すよう指示し、形式外の出力は表示しない
- Content-Security-Policy などのセキュリティヘッダーを付けて配信

## 開発

```bash
npm install
npm run geo          # 地図データを作り直す（通常は不要。生成済みJSONを同梱）
npm run build        # dist/ に出力
npm run dev:worker   # Worker を http://127.0.0.1:8787 で起動（AIはリモート専用のため要ログイン）
npx wrangler dev -c wrangler.local.jsonc --port 8787   # AIなしでローカル起動
npm run dev          # 画面だけを Vite で開発（/api は 8787 へ中継）
```

### テスト

```bash
npm run typecheck
npm test             # 単体テスト 39件
npm run test:e2e     # 実ブラウザテスト 14件（Worker を自動起動）
npm run test:load    # 60台が同時に入力する負荷テスト（Worker を起動しておく）
```

E2Eで確認していること：

1. メモ欄と印刷ボタンがなく、絞り込みは「すべて・暖流の魚・寒流の魚」だけ。以前の版のメモのデータは消える
2. 全画面スケルトンが出て、地図の準備後に消える
3. 地球儀が描かれ、宇宙から日本へ寄る。海流の矢印が時間とともに動く（行列と画素の両方で確認）。潮目・寒流・暖流・深さの凡例、「世界」「日本」の切りかえ、日付変更線の上にも海がある（端がない）
4. 入力でピンが出て、同じ産地・同じ魚を足すとピンが大きくなる。同じ産地でも魚がちがえば別のピンになり、重ならずに並ぶ。タップでその産地の魚の一覧
5. 値札の文字列から魚・産地・養殖を読み取る。外国の入力で地球儀を引いてその国へ飛び、暖流の魚・寒流の魚で絞り込める
6. 同じクラスの2台で、Aのシートに書いた内容はBに出ず、サーバーにも送られない。地球儀に入力した魚はBに届く
7. 図鑑のアコーディオンが開閉し、「地球儀で産地を見る」で絞り込みと産地の輪が出る
8. 2台でクラスに入り、片方の入力がもう片方に数秒で届く。再読み込みしてもサーバーから戻る。接続台数の表示
9. AIなしで「地球儀から読み取る」「問いのたね」が動き、ワークシートが保存される
10. どの画面でも横スクロールが出ない
11. 先生がクラスをつくると大きなQRコードが出て、画面のQRコードを実際に読み取るとそのクラスのリンクになる
12. アプリのカメラ（偽のカメラ映像）でQRコードを読み取ってクラスに参加できる
13. 60人が同時に入力しても、すぐに全部が地球儀に出る（59台分の接続から同時に177件を送り、画面の件数がそろうまでの時間を測る）
14. ひらまさが図鑑に写真と情報つきで出て、同じ県でもぶりとは別のピンになる

負荷テスト（`npm run test:load`）の結果（手元の開発用サーバー）：60台が3件ずつ同時に入力して、60台全員に180件がそろうまで約0.3秒。100台が5件ずつでも約0.7秒。

## 公開（Cloudflare）

どちらか一つ。

**A. Cloudflare のダッシュボードから（おすすめ・トークン不要）**
Workers & Pages →「作成」→「Gitリポジトリをインポート」→ このリポジトリを選ぶ。ビルドコマンド `npm run build`、デプロイコマンド `npx wrangler deploy`。以後、main へのpushで自動公開される。

**B. GitHub Actions から**
リポジトリの Settings → Secrets に `CLOUDFLARE_API_TOKEN`（Workers・Durable Objects・Workers AI の編集権限）と `CLOUDFLARE_ACCOUNT_ID` を登録すると、テスト合格後に自動でデプロイされる。

Durable Objects（SQLite）と Workers AI は無料プランでも使える範囲で動く。

## サーバーなしの1ファイル版

`npm run build:standalone` で `dist-standalone/index.html` を作る。1つのHTMLだけで動き、データはその端末に保存される（クラスの共有とAIは使えない）。

## 出典と注意

- 陸地：Natural Earth（パブリックドメイン）
- 魚の写真：Wikimedia Commons。撮影者とライセンスはアプリの図鑑と [docs/CREDITS.md](docs/CREDITS.md) に記載
- 海流・大陸棚・海溝の位置は、地図帳などで一般的に示される概略を教材用に描いたもので、季節や年による変化は表していない
- 図鑑の内容は一般に教科書や水産庁の資料で扱われる範囲にとどめ、細かな順位や数値は載せていない
- 産地のピンは、その都道府県・国の中で魚がとれる・育てられる場所の近くに置いた目安
